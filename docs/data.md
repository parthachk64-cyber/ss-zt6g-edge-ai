# Data

**The paper's workload and security data are not identified and not public.** The article describes a simulated testbed and names no dataset, releases no traces, labels, splits or class balance. Nothing in this repository stands in for them, and no generated traffic is presented as original measurement.

The machine-readable registry is [`datasets/registry.json`](../datasets/registry.json): origin, access terms, version, SHA-256 of every file, fields, observation times, label and split membership, exclusions. A test checks every hash against the files.

## What is bundled (all synthetic, MIT licence, no personal or provider data)

Generated by `sszt6g build-fixtures` from fixed seeds; a test regenerates them and compares byte hashes.

| File | Role | Contents |
|---|---|---|
| `examples/fixtures/arrivals_ramp_burst_seed1001.csv` | job demand (data plane) | one 120 s ramp-burst scenario, 2,096 jobs: id, time, ingress, tenant, service, work, deadline. No outcome fields. |
| `examples/fixtures/security_events.jsonl` | detector inputs (management plane) | 1,815 signed management requests over 12 episodes of 30 minutes: token, operation, resource, quota total, policy revision, request nonce. **No label, attack kind, episode id or scenario name.** |
| `examples/fixtures/security_labels.csv` | labels, analysis only | per event: label (1 = attack), `attack_kind` (expired identity, tenant mismatch, replay, bad signature, credential misuse), `benign_kind` (burst, degraded posture, near expiry, rare op). |
| `examples/fixtures/security_splits.csv` | split membership | whole episodes, chronological: train 0-6, dev 7-8, test 9-11. |
| `examples/fixtures/intents.jsonl` | tenant provisioning intents | 12 deliveries of 10 unique intents (2 duplicates), with signed local tokens. |
| `examples/fixtures/intent_eligibility.csv` | eligibility, fixed from policy alone | computed from the static policy before any controller runs; never from a run outcome. |

Job demand, security labels and orchestration outcomes are kept in separate files. Outcomes only ever appear in `runs/<id>/`.

## Seeded generator

`sszt6g.workload.make_scenario(kind, seed)` produces a non-homogeneous Poisson arrival process (`steady_low`, `ramp_burst`, `step_burst`) with log-normal service demands and 1% requests from an unauthorized tenant (recorded as `denied`). The same kind and seed always give identical jobs; benchmark seeds (1001-1008) are disjoint from forecaster training seeds (1-24) and development seeds (501-504). Training scenarios use peaks and ramp lengths never used in the test scenarios.

Scenario magnitudes (peak 24 jobs/s against a base of 6, a 20 s ramp, 2 initial servers, 4 s provisioning delay) were **chosen by the implementer**. Do not read field performance into them.

## Import contract for authorized, de-identified edge telemetry

Bring your own data only if you are authorized to use it and it is de-identified. Check it first:

```bash
sszt6g data-check --kind arrivals --path my_arrivals.csv
```

Arrivals CSV columns: `job_id, t_ms, ingress, tenant, service, work_ms, deadline_ms`; timestamps non-decreasing, numeric fields parseable. Replay it with `sszt6g replay --arrivals my_arrivals.csv --planner reactive`. Telemetry records follow the `telemetry` contract v1 (`ts_ms, service, site, ingress_arrivals, routed_arrivals, queue_depth, allocated, busy`; see `src/sszt6g/interfaces.py`). The security check refuses an input file that carries any label-like field (`label`, `attack`, `scenario`, `outcome`, `episode`, `split`).

If a later version of the paper, or its authors, identifies a source, add an adapter for that exact release and document how to obtain it. Do not merge it silently with the synthetic fixtures.

## Exclusions

* No outcome field, label, attack kind or scenario name is a detector input (`detection.FEATURES` is checked against forbidden tokens in a test).
* Detector statistics (rate baseline, operation frequency) are fitted on the training partition only, without labels. The decision threshold is chosen on the development partition only. The test partition is read once, for reporting.
* The 97.5% figure is never a target: no threshold, class mix or feature was tuned toward it.
